# Prompt A/B Testing Harness for Grounding Failures

## Context

The full grounding pipeline scores 9/15 exact code match (60%) and has 3 relation mismatches against our golden test data. The 9 failures break into two categories:

- **6 code mismatches** — MedGemma selects a wrong CUI (subspecific variant, alternate version, or close synonym)
- **3 relation mismatches** — Field mapper generates wrong operator (inverted, wrong class, or missed negation)

We need a test harness that runs **only the failing entities** with **multiple prompt variants** and produces a comparison report showing which variants fix which failures.

## Files to Create

### 1. `tests/e2e/prompt_variants.py` — Variant definitions (pure data)

Defines all prompt variant content as dicts. Each variant has:
- `name`: short label
- `grounding_system`: replacement system prompt (or `None` for baseline)
- `grounding_evaluate`: replacement Jinja2 evaluate template (or `None`)
- `field_mapper_rules_extra`: extra rules to append to field mapper prompt (or `None`)

**MedGemma Variants** (for code selection — 4 variants):

| Variant | Name | Changes |
|---------|------|---------|
| A | `baseline` | No changes — current production prompts |
| B | `specificity_guard` | Add 2 rules to `grounding_system.jinja2`: (1) prefer parent concept over subspecific variants when entity text has no qualifier, (2) prefer primary CUI over alternates when preferred_terms are near-identical |
| C | `context_emphasis` | Modify `grounding_evaluate.jinja2` instructions: add cross-check step — if candidate adds a qualifier not in entity text (e.g. "Juvenile", "Ectopic"), it's too specific; prefer unqualified parent |
| D | `combined` | Both B and C together |

**Field Mapper Variants** (for relation extraction — 2 variants):

| Variant | Name | Changes |
|---------|------|---------|
| A | `baseline` | No changes |
| B | `operator_rules` | Append 3 rules: (1) extract comparison operators verbatim from text, never invert; (2) `within` only for numeric min/max ranges, not discrete categorical lists; (3) negation patterns (`non-`, `not `, `no `) map to `relation='!='` |

1. Load `test_snippets.json`, extract only failing entities
