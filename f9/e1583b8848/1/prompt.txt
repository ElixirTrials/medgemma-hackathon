# Fix Gemini Structured Output Repetition Loop

## Context

Production is producing repeating digit artifacts like `"2202202020202020..."` in field mapping values. Root cause investigation confirmed:

- **Source**: 100% from `gemini_field_mapping` spans — `ChatGoogleGenerativeAI.with_structured_output(FieldMappingResponse)`
- **NOT** MedGemma, structure_builder, or ordinal_resolver
- **Frequency**: 10 out of 547 field_mapping spans (1.8%), concentrated on compound criteria
- **Root cause**: Optional Pydantic fields with `default=None` produce JSON schemas without `required`, which triggers the known Gemini repetition loop bug ([cookbook#449](https://github.com/google-gemini/cookbook/issues/449))
- **DRY problem**: 5 identical `ChatGoogleGenerativeAI(...)` instantiations across 3 files — only `create_structured_llm()` would get the fix, leaving 4 inline usages unprotected

## Fix: 3 Layers

### Layer 1: Consolidate All Gemini Structured Output Through `create_structured_llm()`

Currently 5 places create `ChatGoogleGenerativeAI` with identical params:

| File | Function | Schema | Currently uses `create_structured_llm()`? |
|------|----------|--------|------------------------------------------|
| `gemini_utils.py:138` | `create_structured_llm()` | any | YES (is the utility) |
| `medgemma_decider.py:145` | `_structure_decision_with_gemini()` | `GroundingDecision` | NO — inline |
| `medgemma_decider.py:311` | `_structure_reasoning_with_gemini()` | `AgenticReasoningResult` | NO — inline |
| `entity_decomposer.py:119` | `decompose_entities()` | `DecomposedEntityList` | NO — inline |
| `entity_decomposer.py:224` | `medgemma_decompose_entities()` | `DecomposedEntityList` | NO — inline |

**Change**: Replace all 4 inline `ChatGoogleGenerativeAI(...)` + `.with_structured_output()` calls with `create_structured_llm(Schema)`. This ensures all Gemini structured output calls get the same parameters, Ollama fallback, and future fixes.

Each callsite handles `None` return (no LLM backend) by raising or returning an empty result, which matches existing error handling patterns.

### Layer 2: Fix Generation Parameters in `create_structured_llm()`

Add temperature and repetition penalties — applies to ALL 5 callsites via the consolidation:

```python
gemini = ChatGoogleGenerativeAI(
    model=gemini_model_name,
    google_api_key=google_api_key,
    max_output_tokens=2048,
    temperature=0.1,                          # was: unset (default ~1.0)
    model_kwargs={
        "frequency_penalty": 0.8,             # penalize token repetition
        "presence_penalty": 0.5,              # encourage topic diversity
    },
)
```

### Layer 3: Make All Pydantic Schema Fields Required

Change `default=None` / `default_factory=list` to `Field(...)` so ALL fields appear in JSON schema `required` arrays:

**`FieldMappingValue`** — `required: ["type"]` -> `required: ["type", "value", "unit", "min", "max", "duration"]`
**`FieldMappingItem`** — add `unit`, `value_concept_id`, `value_concept_system` to required
**`FieldMappingResponse`** — `required: []` -> `required: ["mappings"]`

```python
# BEFORE:
value: str | None = Field(default=None, description="...")
# AFTER:
value: str | None = Field(..., description="...")
```

### Layer 4: Safety Net — Detection + Retry (already implemented)

Keep the existing defenses in `gemini_utils.py` and `field_mapper.py`:
- `is_repetition_loop()` detection
- `check_model_for_repetition()` recursive inspector
- `sanitize_repetition_artifacts` Pydantic validator
- 3-attempt retry loop in `generate_field_mappings()`
