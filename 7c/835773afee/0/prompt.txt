# Plan: Separate Value/Unit in Grounding Fixtures + Link Units to Terminology

## Context

The `test_snippets.json` golden fixtures embed units inside value strings (e.g. `"value": "45 ml/min"`). The pipeline already separates value from unit internally (`FieldMappingValue` has typed value + unit fields, `AtomicCriterion` has `unit_text` + `unit_concept_id`), and `normalize_unit()` already returns `(ucum_code, omop_concept_id)` — but the UCUM code is discarded at `structure_builder.py:235`. The test fixtures and DB schema should be brought in line with the pipeline's actual capability.

**Goal**: Separate value from unit in golden examples, add unit terminology codes (UCUM + OMOP), persist UCUM codes through the pipeline, and fix the FHIR exporter's hardcoded unit code.

---

**File**: `tests/e2e/test_snippets.json`

Split each grounding entity's `value` into separate fields:

**Design note — UCUM + OMOP only, no UMLS/SNOMED for units**: UCUM is the mandated standard for units in both FHIR (`system: "http://unitsofmeasure.org"`) and OMOP CDM. UMLS CUIs and SNOMED codes exist for some units but are not used by any interoperability standard. Adding them would create maintenance burden with no downstream benefit.
